# External anchor protocol: synthetic, uninstalled model

Run `node --test tests/prototypes/runner-external-anchor-model.test.mjs`. Nothing imports this model in Pilot. It has no network, OCI, filesystem persistence, process control or actual runtime. `events` are simulated outcomes, not dispatches or termination evidence.

The fake authority and journal are separate in-memory objects. Owner provisioning is distinct from ordinary transitions; interruptions leave state in place. Each transition compares the full modeled journal digest, commits the modeled journal first, then CASes, and only a live synthetic continuation records an event. Errors after a transition enters its protected body stop admission. A concurrent call rejected as busy does not latch the model closed or cancel the held transition. Inspection never reconciles or replays; explicit synthetic owner enable requires equality and an asserted predecessor fence. Tombstones and dispatch-possible records survive inspection. A held async transition prevents another model transition, and restart invalidates its generation.

**Critical boundary:** the synchronous generation check and event append are only atomic in this single JavaScript event loop. They do not model a host-level lock, credentials, separate processes, runtime invocation, or a predecessor paused between a check and an external effect. No sound physical continuation fence is provided; real admission must remain closed. The synthetic owner assertion is not evidence that a real predecessor is fenced. Reopening after equality does not settle previous effects.

The model deliberately omits SQLite/WAL, transaction isolation, fsync and power loss, schema/history validation, randomized identity allocation, real authentication/freshness/equivocation detection, credential revocation, policy/budget integration, supervisor/runtime behavior, and privileged recovery transactions. Fault labels for stale, malformed, unauthorized and equivocal responses model *detected errors*, not detection of plausible forged replies. The fake CAS assumes its code and memory are authoritative and durable; it does not establish any provider's semantics. Authority loss, both-side rollback, identity/config substitution, or compromised verifier are not prevented. The both-side rollback test is an explicit indistinguishability counterexample. This prototype makes no physical anti-rollback, runtime termination, production readiness or deployment claim.
